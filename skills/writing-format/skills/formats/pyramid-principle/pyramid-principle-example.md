# 피라미드 원칙 예시

## 주문 수집을 병렬 처리로 바꿔야 한다

주문 수집을 쇼핑몰 4곳씩 동시에 호출하도록 바꾸자. 지금 방식으로는 수집 주기를 지킬 수 없고, 병렬 처리는 효과가 크며, 바꾸는 비용과 위험은 작다.

### 1. 지금 방식으로는 수집 주기를 지킬 수 없다

- 쇼핑몰 40곳을 차례로 호출해서 한 번 수집에 평균 12분이 걸린다.
- 수집 주기는 10분이라서, 이전 수집이 끝나기 전에 다음 수집이 시작된다.
- 연동 쇼핑몰은 매달 3곳 정도씩 늘고 있어서, 시간은 앞으로 더 늘어난다.

### 2. 병렬 처리로 바꾸면 효과가 크다

- 4곳씩 동시에 호출하면 수집 시간이 3분 20초로 줄어든다.
- 쇼핑몰이 100곳으로 늘어도 계산상 9분 안에 끝난다.

### 3. 바꾸는 데 드는 비용과 위험이 작다

- 수집 코드는 그대로 두고, 쇼핑몰을 나눠 돌리는 부분만 바꾸면 된다. 개발에 3일이 걸린다.
- 4곳씩 호출할 때는 쇼핑몰이 호출을 거절한 일이 없었다.
- 설정값 하나로 예전 방식으로 바로 되돌릴 수 있다.
