# arc42 예시

## 주문 수집 시스템 아키텍처 문서

### 1. 소개와 목표

연동 쇼핑몰 40곳에서 새 주문을 모아 창고 시스템으로 넘긴다.
품질 목표는 세 가지다. 앞에 있을수록 중요하다.

1. 주문을 빠뜨리지 않는다.
2. 같은 주문을 창고 시스템에 두 번 넘기지 않는다.
3. 10분마다 한 번씩 수집을 끝낸다.

| 이해관계자    | 바라는 것                                     |
|---------------|-----------------------------------------------|
| 고객사 담당자 | 주문이 들어온 뒤 10분 안에 관리 화면에서 본다 |
| 창고 운영팀   | 같은 주문을 두 번 출고하지 않는다             |
| 주문팀 개발자 | 쇼핑몰이 늘어도 구조를 바꾸지 않고 버틴다     |

### 2. 제약

- 쇼핑몰마다 짧은 시간에 호출할 수 있는 횟수가 정해져 있다.
- 쇼핑몰 40곳 가운데 주문이 생겼다고 알려 주는 곳은 6곳뿐이라, 나머지는 우리가 찾아가서 물어봐야 한다.
- 고객사와 10분 안에 주문을 반영하기로 약속했다.

### 3. 맥락과 범위

- 쇼핑몰 40곳: 우리가 새 주문을 조회한다.
- 창고 시스템: 우리가 모은 주문을 넘긴다.
- 고객사 담당자: 관리 화면에서 수집 현황을 본다.

### 4. 해결 전략

쇼핑몰을 4곳씩 동시에 호출한다. 동시 호출 수는 설정값으로 둬서 배포 없이 바꿀 수 있게 한다.

### 5. 구성 요소 관점

| 구성 요소        | 하는 일                                  |
|------------------|------------------------------------------|
| 수집 스케줄러    | 10분마다 수집을 시작한다                 |
| 작업 대기열      | 수집할 쇼핑몰 목록을 담는다              |
| 일꾼             | 대기열에서 쇼핑몰을 하나씩 꺼내 수집한다 |
| 쇼핑몰 연동 모듈 | 쇼핑몰마다 다른 API 호출 방식을 맞춘다   |
| 주문 저장소      | 수집한 주문을 데이터베이스에 저장한다    |

### 6. 실행 관점

한 번 수집은 이렇게 돈다.

1. 수집 스케줄러가 쇼핑몰 40곳을 작업 대기열에 넣는다.
2. 일꾼 4개가 쇼핑몰을 하나씩 꺼내 새 주문을 조회한다.
3. 쇼핑몰이 호출을 거절하면 그 쇼핑몰을 30초 뒤에 대기열에 다시 넣는다.
4. 조회한 주문은 주문 저장소에 저장한다.
5. 대기열이 비면 이번 수집을 끝낸다.

### 7. 배포 관점

수집 서버 한 대와 주문 데이터베이스 한 대로 운영한다.

### 8. 공통 개념

- 쇼핑몰 호출은 세 번까지 다시 시도한다. 세 번 모두 실패하면 알림을 보낸다.
- 로그마다 쇼핑몰 이름을 넣는다.

### 9. 설계 결정

- ADR 0012: 주문 수집은 쇼핑몰 4곳씩 동시에 호출한다.

### 10. 품질 요구

1절의 품질 목표마다 확인할 수 있는 상황을 하나씩 정했다.

| 품질 목표         | 상황                                          | 기대하는 반응                                    | 재는 방법                           |
|-------------------|-----------------------------------------------|--------------------------------------------------|-------------------------------------|
| 빠뜨리지 않음     | 쇼핑몰 한 곳이 세 번 연속으로 호출을 거절한다 | 그 쇼핑몰의 주문을 다음 주기에 빠짐없이 수집한다 | 쇼핑몰 주문 목록과 저장한 주문 비교 |
| 두 번 넘기지 않음 | 수집 도중에 수집 서버가 다시 켜진다           | 이미 넘긴 주문을 창고 시스템에 또 넘기지 않는다  | 창고 시스템의 주문 번호 중복 수     |
| 10분 주기         | 연동 쇼핑몰이 100곳으로 늘어난다              | 한 번 수집을 10분 안에 끝낸다                    | 수집 기록의 시작 시각과 끝 시각     |

### 11. 위험과 기술 부채

- 쇼핑몰마다 호출 제한이 다른데, 동시 호출 수는 모든 쇼핑몰에 똑같이 적용한다.
- 수집 서버가 한 대라서, 서버가 멈추면 수집도 멈춘다.

### 12. 용어

- 수집 주기: 한 번 수집을 시작하고 다음 수집을 시작할 때까지의 시간이다.
- 일꾼: 쇼핑몰 하나를 맡아 수집하는 실행 단위다.
