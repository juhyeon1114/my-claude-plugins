# 문제, 원인, 해결, 효과

문제를 고친 과정을 문제, 원인, 해결, 효과 순서로 푸는 글쓰기 양식이다. 개선 사례를 공유할 때 쓰고, 사내 기술 블로그나 개선 사례 발표에 많이 쓴다.
STAR와 비슷하지만, 사람이 아니라 문제에 초점을 둔다. "누가 했는가"보다 "무엇을 어떻게 고쳤는가"가 중심이다.

## 구성

1. 문제: 무엇이 불편하거나 잘못됐는지 쓴다. 가능하면 숫자로 쓴다.
2. 원인: 문제가 왜 생겼는지 쓴다. 증상이 아니라 원인을 쓴다.
3. 해결: 원인을 어떻게 없앴는지 쓴다.
4. 효과: 해결 뒤 무엇이 달라졌는지 문제에서 쓴 숫자와 비교해서 쓴다. 잰 값과 계산한 값은 구분한다.

문제와 효과를 같은 기준으로 재야 한다. 그래야 얼마나 나아졌는지 한눈에 비교할 수 있다.

## 자주 하는 실수

- 원인 자리에 증상을 쓴다. "수집이 느렸다"는 원인이 아니라 문제다.
- 문제와 효과를 다른 기준으로 잰다. 문제는 시간으로 쓰고 효과는 만족도로 쓰면 비교할 수 없다.
- 계산으로 낸 효과를 잰 효과처럼 쓴다.

## 참고 자료

- Michael Hoey, On the Surface of Discourse (George Allen & Unwin, 1983): 상황, 문제, 대응, 평가로 이어지는 문제 해결 패턴을 정리한 책이다. 이 양식의 바탕이 되는 짜임이다.
