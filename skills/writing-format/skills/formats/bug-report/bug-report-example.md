# 버그 리포트 예시

## 병렬 수집에서 호출을 거절한 쇼핑몰이 두 번 수집된다

심각도와 영향
- 심각도: 높음. 9월 28일 운영 적용 전에 고쳐야 한다.
- 운영에서 생기면 같은 주문이 창고 시스템에 두 번 넘어가서 두 번 출고될 수 있다.

환경
- 검증 서버
- 주문 수집 버전 2.4.0
- 설정값 `order.collect.concurrency`는 4

재현 절차
1. 검증 서버의 가짜 쇼핑몰 A가 첫 번째 호출을 항상 거절하도록 설정값 `mock.mall-a.reject-first`를 `true`로 바꾼다.
2. 주문 수집을 한 번 실행한다.
3. 수집이 끝날 때까지 기다린다. 쇼핑몰 A는 거절당한 뒤 30초 뒤에 다시 호출된다.
4. 쇼핑몰 A의 수집 기록과 저장된 주문을 확인한다.

기대한 결과
쇼핑몰 A는 이번 주기에 한 번만 수집된다. 수집 기록도 한 줄만 남는다.

실제 결과
쇼핑몰 A가 두 번 수집된다. 수집 기록이 두 줄 남고, 같은 주문 12건이 두 번씩 저장됐다.
10번 해 보면 10번 모두 같은 결과가 나온다.
`order.collect.concurrency`를 1로 바꾸면 생기지 않는다.

참고 자료
- 수집 기록 번호: 88121, 88125
- 두 번 저장된 주문 번호: 첨부한 목록 참고
- 거절 직후에 다시 시도가 두 번 예약된 로그를 첨부했다.
