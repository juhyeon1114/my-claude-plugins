# C4 모델

소프트웨어 구조를 그림으로 보여 주는 방법이다. 사이먼 브라운 (Simon Brown)이 만들었다.
지도를 확대하듯 네 단계로 그린다. 한 그림에는 한 단계만 담는다.
여기서 컨테이너는 도커 컨테이너가 아니라, 따로 실행되거나 따로 데이터를 저장하는 단위를 말한다. 서버 애플리케이션, 웹 앱, 데이터베이스 같은 것이다.

## 구성

1. 시스템 맥락 (System Context): 이 시스템을 누가 쓰고, 어떤 외부 시스템과 주고받는지 그린다.
2. 컨테이너 (Container): 시스템 안의 컨테이너와 그 사이의 통신을 그린다.
3. 컴포넌트 (Component): 컨테이너 하나를 골라 안쪽 구성 요소를 그린다.
4. 코드 (Code): 컴포넌트 하나의 클래스 구조를 그린다. 보통 IDE로 보면 되므로 그리지 않는다.

그림을 그릴 때 지키는 규칙은 다음과 같다.

- 그림마다 제목과 범례를 둔다. 제목에는 몇 단계 그림인지와 범위를 쓴다.
- 상자마다 종류와 하는 일을 쓴다. 종류는 사람, 시스템, 컨테이너, 컴포넌트 가운데 하나다. 컨테이너와 컴포넌트는 쓰는 기술도 쓴다.
- 2단계부터는 시스템 경계를 그려서, 경계 안과 밖을 구분한다.
- 선은 한 방향 화살표로만 그린다. 선마다 무엇을 하는지 구체적으로 이름을 붙인다. "사용한다"처럼 막연한 이름은 쓰지 않는다.
- 설명 없이 그림만 봐도 대부분 이해할 수 있어야 한다.

이 네 단계 말고도 보조 그림이 세 가지 있다. 여러 시스템을 한꺼번에 보여 주는 시스템 지형 그림, 동작 순서를 보여 주는 동적 그림, 서버 배치를 보여 주는 배포 그림이다.

## 자주 하는 실수

- 한 그림에 여러 단계를 섞는다. 예를 들어 시스템 맥락 그림에 데이터베이스를 그린다.
- 상자에 이름만 쓰고 종류와 하는 일을 빠뜨린다.
- 선에 "사용한다"처럼 막연한 이름을 붙이거나, 양쪽 화살표를 쓴다.
