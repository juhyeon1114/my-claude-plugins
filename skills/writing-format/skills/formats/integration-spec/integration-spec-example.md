# 외부 연동 명세 예시

## 가나몰 주문 수집 연동 명세

작성자: 김주현
기준 문서: 가나몰 Open API v2 (2026년 8월 판)
상태: 작성 중 (확인하지 못한 것 3건)

### 개요

가나몰에서 새 주문과 주문 취소를 가져와 우리 주문으로 저장한다. 41번째 연동 쇼핑몰이다.

### 범위

- 연동하는 기능: 주문 목록 조회, 주문 상세 조회, 취소된 주문 조회
- 연동하지 않는 기능: 송장 번호 보내기, 반품 조회. 송장 번호 보내기는 다음 단계에서 명세를 따로 쓴다.

### 인증 방식

- OAuth 2.0으로 받은 접근 토큰을 요청 헤더 `Authorization`에 넣는다.
- 접근 토큰은 발급하고 4시간 뒤에 만료된다. 만료 30분 전에 갱신 토큰으로 새 접근 토큰을 받는다.
- 갱신 토큰은 30일 동안 쓸 수 있다. 30일 동안 한 번도 갱신하지 않으면 고객사가 가나몰에서 연동을 다시 승인해야 한다.
- 근거: API 문서 "인증" 장

### 호출 제한

- 판매자 계정 하나당 1초에 10번, 1분에 300번까지 호출할 수 있다.
- 제한을 넘으면 HTTP 429 응답이 온다. 응답 헤더 `Retry-After`에 기다려야 할 초가 담겨 온다.
- 주문 목록 조회는 한 번에 최대 100건까지 받는다. 조회 기간은 최대 24시간이다.
- 근거: API 문서 "호출 제한" 장, "주문 목록 조회" 장

### 필드 매핑표

| 가나몰 필드                              | 우리 필드               | 비고                                                       |
|------------------------------------------|-------------------------|------------------------------------------------------------|
| `order_no`                               | `Order.externalOrderNo` | 중복 저장을 막는 기준이다                                  |
| `ordered_at`                             | `Order.orderedAt`       | 세계 표준시 (UTC) 문자열로 온다. 한국 시간으로 변환한다    |
| `receiver.name`                          | `Order.receiverName`    |                                                            |
| `receiver.phone`                         | `Order.receiverPhone`   | 실제 번호 대신 안심번호로 올 수 있다                       |
| `receiver.address1`, `receiver.address2` | `Order.receiverAddress` | 두 필드를 공백 하나로 이어 붙인다                          |
| `items[].sku`                            | `OrderLine.sku`         | 비어 올 수 있다. 비면 `items[].product_id`로 상품을 찾는다 |
| `items[].qty`                            | `OrderLine.quantity`    |                                                            |
| `items[].price`                          | `OrderLine.unitPrice`   | 문자열로 온다. 숫자로 변환한다                             |

근거: API 문서 "주문 상세 조회" 장의 응답 예시

### 주문 상태 매핑표

| 가나몰 상태        | 우리 상태          | 처리                                        |
|--------------------|--------------------|---------------------------------------------|
| `PENDING_PAYMENT`  | 짝 없음            | 결제 전 주문이라 가져오지 않는다            |
| `PAID`             | `RECEIVED`         | 새 주문으로 저장한다                        |
| `PREPARING`        | `RECEIVED`         | 이미 저장한 주문이면 바꾸지 않는다          |
| `CANCEL_REQUESTED` | `CANCEL_REQUESTED` | 아직 출고 전이면 출고를 막는다              |
| `CANCELLED`        | `CANCELLED`        | 출고 전이면 창고 작업을 취소한다            |
| `SHIPPED`          | 짝 없음            | 우리가 출고한 결과라서 따로 저장하지 않는다 |

근거: API 문서 "주문 상태" 부록

### 오류 응답과 재시도 규칙

| 응답                    | 다시 시도                            | 포기하면                                      |
|-------------------------|--------------------------------------|-----------------------------------------------|
| 429 호출 제한 초과      | `Retry-After`만큼 기다린 뒤 최대 3번 | 이번 주기에서 건너뛰고 알림을 보낸다          |
| 500, 502, 503 서버 오류 | 30초 뒤에 최대 3번                   | 이번 주기에서 건너뛰고 알림을 보낸다          |
| 401 토큰 만료           | 토큰을 갱신한 뒤 1번                 | 고객사에 연동 재승인을 요청하는 알림을 보낸다 |
| 400 잘못된 요청         | 하지 않는다                          | 바로 알림을 보낸다. 우리 요청이 잘못된 것이다 |

근거: API 문서 "오류 코드" 장

### 변경 알림 지원 여부

- 새 주문과 주문 취소를 웹훅으로 알려 준다.
- 알림에는 주문 번호와 상태만 담긴다. 주문 내용은 주문 상세 조회로 따로 가져와야 한다.
- 알림을 받지 못했을 때 다시 보내 주는지는 문서에 없다.
- 이번 연동에서는 웹훅을 쓰지 않고, 10분마다 주문 목록을 조회한다.
- 근거: API 문서 "웹훅" 장

### 확인하지 못한 것

- 주문 목록 조회 결과가 주문 시각 순서로 오는지 문서에 없다. 순서가 섞여 오면 페이지를 넘기는 사이에 주문을 빠뜨릴 수 있다. 시험 계정으로 확인한다.
- 판매자가 취소 요청을 거절하면 `CANCEL_REQUESTED`가 어떤 상태로 바뀌는지 문서에 없다. 시험 계정으로 확인한다.
- 1분에 300번 제한이 판매자 계정마다 따로인지, 우리 앱 전체를 합친 것인지 문서마다 다르게 적혀 있다. 9월 24일에 가나몰 개발자 지원 창구에 물었고 답을 기다리고 있다.
