# 외부 연동 명세

외부 서비스의 API를 우리 시스템에 붙이기 전에, 무엇을 어떻게 주고받는지 정리하는 문서다. 외부 서비스는 쇼핑몰이나 배송사 같은 곳이다.
외부 API 문서를 옮겨 적지 않는다. 우리 시스템에 필요한 것만 골라서, 우리 필드와 우리 상태에 짝지어 적는다.
이름이 정해진 표준 양식은 아니다. 조사 보고서처럼 확인한 사실과 확인하지 못한 것을 나눠 쓴다.

## 구성

1. 개요: 어느 서비스와 무엇을 주고받는지 쓴다. 기준으로 삼은 API 문서와 그 문서의 판도 쓴다.
2. 범위: 이번에 연동하는 기능과 연동하지 않는 기능을 쓴다.
3. 인증 방식: 어떤 방식으로 인증하는지, 토큰이 언제 만료되고 어떻게 갱신하는지 쓴다.
4. 호출 제한: 정해진 시간에 몇 번까지 호출할 수 있는지, 넘으면 어떤 응답이 오는지 쓴다.
5. 필드 매핑표: 외부 필드와 우리 필드를 짝지어 쓴다. 변환이 필요하거나 비어 올 수 있는 필드는 비고에 쓴다.
6. 주문 상태 매핑표: 외부 상태와 우리 상태를 짝지어 쓴다. 짝이 없는 상태를 어떻게 처리할지도 쓴다.
7. 오류 응답과 재시도 규칙: 오류마다 다시 시도할지, 얼마 뒤에 몇 번 할지, 포기하면 무엇을 할지 쓴다.
8. 변경 알림 지원 여부: 외부 서비스가 변경을 먼저 알려 주는 웹훅 (Webhook)을 지원하는지 쓴다. 지원하면 무엇을 알려 주는지도 쓴다.
9. 확인하지 못한 것: 문서에 없거나 문서와 실제가 다를 수 있어서 시험해 봐야 하는 것을 쓴다.

항목마다 근거가 된 API 문서의 위치를 붙인다. 외부 API가 바뀌었을 때 어느 부분을 다시 볼지 알 수 있다.

## 자주 하는 실수

- 외부 API 문서를 통째로 옮겨 적는다. 우리가 쓰지 않는 필드까지 적으면 정작 중요한 매핑이 묻힌다.
- 짝이 없는 상태나 비어 올 수 있는 필드를 빠뜨린다. 운영에서 생기는 연동 오류는 주로 이런 예외에서 난다.
- 문서로 확인한 것과 시험으로 확인한 것을 구분하지 않는다. 외부 API 문서는 실제 동작과 다를 때가 많다.
- 확인하지 못한 것을 적지 않는다. 읽는 사람은 모든 항목이 확인된 사실이라고 여긴다.
