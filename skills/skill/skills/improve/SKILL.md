기준 문서: https://platform.claude.com/docs/ko/agents-and-tools/agent-skills/best-practices

## 1단계: 대상 읽기

1. 사용자가 지정한 스킬 디렉터리의 파일을 모두 읽는다. 지정하지 않았으면 어떤 스킬인지 묻는다.
2. 사용자가 실제 사용 중 겪은 문제를 말했으면 그 문제부터 고친다.

## 2단계: 점검

아래 체크리스트를 응답에 복사해 항목마다 통과 여부를 표시한다.

```
메타데이터
- [ ] name: 64자 이하, `anthropic`·`claude` 미포함, `helper`·`utils` 같은 모호한 이름 아님
- [ ] description: 1,024자 이하, XML 태그 없음, 3인칭
- [ ] description: 무엇을 하는지와 언제 쓰는지(트리거 문구)를 모두 담음

본문
- [ ] Claude가 이미 아는 설명이 없음. Claude가 반복하는 실수를 짚는 문장은 지식이 아니라 교정이므로 남긴다
- [ ] 자유도가 작업에 맞음: 실수하기 쉬운 작업은 정확한 명령, 판단이 필요한 작업은 원칙만
- [ ] 선택지를 나열하지 않고 기본값 하나와 예외만 둠
- [ ] 같은 대상을 한 용어로만 부름
- [ ] 시간이 지나면 틀리는 정보가 없음
- [ ] 예시가 구체적임. 출력 형식이 중요하면 템플릿이나 입력/출력 쌍이 있음
- [ ] 다단계 작업은 번호 단계로 나뉨. 품질이 중요하면 검증 → 수정 → 재검증 루프가 있음

구조
- [ ] SKILL.md 본문이 500줄 미만. 넘으면 세부 내용을 별도 파일로 분리
- [ ] 참조 파일은 SKILL.md에서 한 단계 깊이로만 연결
- [ ] 100줄 넘는 참조 파일은 맨 위에 목차가 있음
- [ ] 파일 이름이 내용을 드러내고 경로는 슬래시(/)를 씀

스크립트 (있을 때만)
- [ ] 오류를 Claude에게 미루지 않고 스크립트가 처리
- [ ] 상수마다 값의 근거가 있음
- [ ] 필요한 패키지를 명시하고 설치되어 있다고 가정하지 않음
- [ ] 스크립트를 실행할지 읽을지 명확함
- [ ] MCP 도구는 서버 접두어가 붙은 완전한 이름으로 부름
- [ ] 되돌리기 어려운 작업 앞에 검증 단계가 있음
```

## 3단계: 고치기

사용자가 고치지 말고 점검만 하라고 했으면 이 단계를 건너뛰고, 4단계에서 통과하지 못한 항목을 우선순위, 스킬, 문제, 제안 열의 표로 보고한다.

1. 통과하지 못한 항목만 고친다. 스킬의 목적과 동작은 바꾸지 않는다.
2. name 변경은 다른 곳의 참조를 깨뜨리므로 제안만 하고 사용자 확인 후 바꾼다.
3. 고친 뒤 2단계를 다시 돌린다. 모든 항목이 통과할 때까지 반복한다.

## 4단계: 보고

- 고친 내용을 항목당 한 줄로 쓴다.
- 고치지 않고 남긴 항목과 그 이유를 쓴다.
