# 원칙

- 새 세션은 이 대화를 보지 못한다. 이 글만 읽고 작업을 이어갈 수 있게 쓴다.
- 글은 마크다운 코드블록 하나에 담아 채팅으로만 보여준다. 파일로 저장하지 않는다.

# 단계

1. 저장소 상태를 기억으로 쓰지 않고 `git status`, `git log`, `git branch --show-current` 로 확인한다. 세션에서 다룬 저장소가 여럿이면 모두 확인한다.
2. 아래 형식으로 쓴다. 쓸 내용이 없는 절은 뺀다.
3. 쓴 글을 새 세션의 입장에서 다시 읽고, 이 대화를 봐야만 알 수 있는 말이 남아 있으면 풀어 쓴다.

# 형식

```markdown
# 목표
# 지금 상태
# 남은 일
# 정해진 것
# 주의할 점
# 관련 위치
```

- 목표: 사용자가 이 작업으로 얻으려는 것을 한두 문장으로 쓴다.
- 지금 상태: 끝낸 일을 쓰고, 일마다 검증했는지와 커밋, 푸시했는지를 밝힌다. 확인하지 못한 것은 확인하지 못했다고 쓴다.
- 남은 일: 할 순서대로 쓴다. 사용자의 답을 기다리는 일은 무엇을 기다리는지 쓴다.
- 정해진 것: 다시 논의하지 않을 결정과 그 이유를 쓴다. 사용자가 거절한 방식도 여기에 쓴다.
- 주의할 점: 실패한 시도와 그 이유, 건드리면 안 되는 것을 쓴다.
- 관련 위치: 파일은 절대 경로로, 브랜치와 커밋, PR, 문서는 이름이나 링크로 쓴다.

# 쓰지 않는 것

- 끝난 일을 어떤 순서로 했는지 같은 과정 설명.
- 코드나 `git log` 를 보면 알 수 있는 세부 내용.
- 이 대화에서만 쓴 약칭. 처음 보는 사람이 아는 이름으로 풀어 쓴다.
