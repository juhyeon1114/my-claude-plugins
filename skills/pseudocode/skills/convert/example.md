# 변환 예시

PR 리뷰 지침 하나를 수도코드를 쓴 지침으로 바꾸는 과정이다.

## 원문

````markdown
# PR 리뷰 지침

PR을 리뷰할 때는 먼저 PR 설명과 연결된 티켓을 읽는다. 변경된 파일이 너무 많으면 사용자에게 어디부터 볼지 묻는다.
파일마다 버그, 빠진 테스트, 이름 짓기를 본다. 버그로 보이는 것은 필요하면 직접 재현해 본다.
코멘트는 정중하게, 한 코멘트에 한 가지만 쓴다. 고칠 방법을 아는 경우에는 제안 코드를 붙인다.
리뷰 결과는 채팅으로만 보여주고 GitHub에는 쓰지 않는다.
사소한 지적이 대부분이면 승인을, 버그가 하나라도 있으면 변경 요청을 권한다.
````

## 바꿀 부분 나누기

| 원문                                         | 판단                                          |
|----------------------------------------------|-----------------------------------------------|
| 설명과 티켓을 읽고, 파일마다 세 가지를 본다  | 수도코드. 순서가 있는 절차와 반복이다         |
| 파일이 많으면 묻는다, 필요하면 재현한다      | 수도코드. 분기다                              |
| 고칠 방법을 알면 제안 코드를 붙인다          | 수도코드. 분기다                              |
| 승인과 변경 요청을 권하는 조건               | 수도코드. 값에 따라 정해지는 결과다           |
| 채팅으로만 보여주고 GitHub에는 쓰지 않는다   | `지킬 것`. 절차 전체에 걸리는 단일 규칙이다   |
| 코멘트는 정중하게, 한 코멘트에 한 가지만     | 자연어. 어조와 정도를 다룬다                  |

분기와 반복이 합쳐서 여섯이라 효과 등급은 높음이다.

## 모호한 표현 정하기

| 원문 표현                                    | 종류                              | 다룬 방법         | 정한 내용              |
|----------------------------------------------|-----------------------------------|-------------------|------------------------|
| "너무 많으면"                                | 값으로 정할 수 있는 것            | 사용자에게 물었다 | 30개를 넘으면          |
| 사소한 지적이 대부분인데 버그도 있을 때      | 원문에 적히지 않은 경우에 할 일   | 사용자에게 물었다 | 변경 요청을 권한다     |
| 버그도 없고 사소한 지적이 대부분도 아닐 때   | 원문에 적히지 않은 경우에 할 일   | 사용자에게 물었다 | 의견만 남기기를 권한다 |
| "필요하면"                                   | 상황을 보고 판단해야 하는 것      | 이름으로 뒀다     |                        |

"고칠 방법을 아는 경우에는"은 아니면 붙이지 않는다는 뜻이 당연히 따라 나오므로 묻지 않았다.

## 바꾼 결과

````markdown
# PR 리뷰 지침

```python
# 수도코드 지침: 이름의 뜻대로 직접 하고, 적힌 순서와 분기를 지킨다. 뜻이 모호하면 사용자에게 묻는다.

최대_파일_수 = 30


def PR_리뷰(PR):
    # 지킬 것: 리뷰 결과는 채팅으로만 보여주고 GitHub에는 쓰지 않는다

    읽기(PR_설명)
    읽기(연결된_티켓)

    파일들 = 바뀐_파일들
    if 파일_수 > 최대_파일_수:
        먼저_볼_파일 = 사용자에게_묻기("변경된 파일이 많다. 어디부터 볼까?")
        앞으로_옮기기(먼저_볼_파일)

    지적_목록 = 빈_목록
    for 파일 in 파일들:
        파일의_지적들 = 파일_리뷰(파일)
        지적_목록에_더하기(파일의_지적들)

    for 지적 in 지적_목록:
        코멘트 = 코멘트_쓰기(지적)
        if 고칠_방법을_앎(지적):
            제안_코드_붙이기(코멘트)
        보여주기(코멘트)

    결론 = 결론_권하기(지적_목록)
    보여주기(결론)


def 파일_리뷰(파일):
    지적들 = 문제_찾기(파일)  # 버그, 빠진 테스트, 이름 짓기
    for 지적 in 지적들:
        if 지적 == 버그 and 재현_필요함(지적):  # 원문: "필요하면"
            재현하기(지적)
    return 지적들


def 결론_권하기(지적_목록):
    if 버그_있음(지적_목록):
        return "변경 요청"
    if 사소한_지적이_대부분(지적_목록):
        return "승인"
    return "의견만 남기기"
```

코멘트는 정중하게, 한 코멘트에 한 가지만 쓴다.
````

## 원문과 대조하기

| 원문 규칙                                    | 바꾼 결과의 위치                               | 상태          |
|----------------------------------------------|------------------------------------------------|---------------|
| 먼저 PR 설명과 연결된 티켓을 읽는다          | `PR_리뷰`의 두 `읽기`                          | 같음          |
| 파일이 너무 많으면 어디부터 볼지 묻는다      | `최대_파일_수`, `사용자에게_묻기`, `앞으로_옮기기` | 사용자가 정함 |
| 파일마다 버그, 빠진 테스트, 이름 짓기를 본다 | 첫 번째 `for`와 `문제_찾기`                    | 같음          |
| 버그로 보이는 것은 필요하면 재현한다         | `파일_리뷰`의 `재현_필요함`                    | 같음          |
| 코멘트는 정중하게, 한 가지만 쓴다            | 블록 아래 자연어                               | 같음          |
| 고칠 방법을 알면 제안 코드를 붙인다          | `고칠_방법을_앎`                               | 같음          |
| 채팅으로만 보여주고 GitHub에는 쓰지 않는다   | `# 지킬 것:`                                   | 같음          |
| 버그가 하나라도 있으면 변경 요청을 권한다    | `결론_권하기`의 첫 번째 `if`                   | 같음          |
| 사소한 지적이 대부분이면 승인을 권한다       | `결론_권하기`의 두 번째 `if`                   | 같음          |
| 없음                                         | `결론_권하기`에서 버그를 먼저 보는 순서        | 사용자가 정함 |
| 없음                                         | `결론_권하기`의 마지막 `return`                | 사용자가 정함 |
