# 수도코드 지침 규약

AI에게 주는 지침 가운데 절차를 수도코드로 쓰는 방법과, 그렇게 쓴 지침을 읽는 방법을 정한다.

## 파일

| 파일                              | 내용                                              | 읽는 때                                          |
|-----------------------------------|---------------------------------------------------|--------------------------------------------------|
| `${CLAUDE_SKILL_DIR}/grammar.md`  | 표기, 뜻이 정해진 함수, 쓰는 규칙, 머리말, 예시   | 수도코드를 쓰거나 바꿀 때, 표기의 뜻을 확인할 때 |
| `${CLAUDE_SKILL_DIR}/criteria.md` | 수도코드로 바꿀지 판단하는 기준, 모호한 표현      | 어느 부분을 수도코드로 쓸지 정할 때              |

## 해석 규칙

수도코드로 쓴 지침을 받았을 때 따른다.

1. 수도코드는 따라야 할 절차다. 코드 실행 도구로 돌리지 않고, 실제 코드로 구현하지 않는다.
2. 순서, 분기, 반복은 적힌 대로 지킨다. 단계를 건너뛰거나 순서를 바꾸지 않는다.
3. 정의가 없는 함수는 이름, 인자, 주석에서 뜻을 읽어 직접 수행한다. 정의가 있는 함수는 정의대로 수행한다.
4. `ask_user`, `report`, `stop`, `run`은 뜻이 정해져 있다. 뜻은 `grammar.md`의 `뜻이 정해진 함수` 표를 따른다.
5. 뜻을 정할 수 없는 함수나 조건을 만나면 추측하지 않고 사용자에게 묻는다.
6. docstring의 `지킬 것`은 그 절차의 모든 단계에 적용한다.
7. 수도코드에 적히지 않은 경우를 만나면 docstring의 목적에 맞게 판단한다. 되돌리기 어려운 동작이 필요하면 먼저 묻는다.
8. 수도코드와 주변 자연어 지침이 어긋나면 어긋난 곳을 사용자에게 알리고 묻는다.
9. 사용자에게 진행 상황을 알릴 때는 함수 이름을 쓰지 않고 자연어로 말한다.
10. `grammar.md`와 다른 표기로 쓴 수도코드는 일반적인 프로그래밍 관례대로 읽고, 위 규칙을 똑같이 적용한다.
