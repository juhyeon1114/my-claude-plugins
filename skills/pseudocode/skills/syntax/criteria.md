# 수도코드로 바꿀지 판단하는 기준

지침의 어느 부분을 수도코드로 쓰고 어느 부분을 자연어로 둘지 정한다.

## 수도코드로 바꾸는 것

| 종류                        | 알아보는 단서                               | 예                                                       |
|-----------------------------|---------------------------------------------|----------------------------------------------------------|
| 순서가 있는 절차            | "먼저", "그다음", "~한 뒤", 번호 단계       | 변경을 확인한 뒤 테스트를 돌리고 커밋한다                |
| 분기                        | "~이면", "~인 경우", "없으면", "단"         | 파일이 있으면 그 규칙을 따르고, 없으면 기본 형식으로 쓴다 |
| 반복                        | "마다", "각각", "모든 ~에 대해"             | 파일마다 오류를 확인한다                                 |
| 되풀이                      | "~할 때까지", "통과하면", "다시"            | 모든 항목이 통과할 때까지 고치고 다시 점검한다           |
| 값에 따라 정해지는 결과     | 우선순위, 대응표, 기준 숫자                 | 적합도가 30% 아래면 후보에서 뺀다                        |
| 여러 곳에서 쓰는 같은 절차  | 같은 단계 묶음이 두 번 이상 나온다          | 커밋 전 점검을 세 스킬이 똑같이 한다                     |

`여러 곳에서 쓰는 같은 절차`는 대상이 파일 여러 개일 때만 본다.

## 자연어로 두는 것

| 종류                    | 예                                         |
|-------------------------|--------------------------------------------|
| 어조와 문체             | 쉬운 말을 먼저 쓴다                        |
| 정도를 다루는 규칙      | 간결하게 쓴다                              |
| 이유와 배경             | 읽는 사람이 처음 본다고 가정하기 때문이다  |
| 분기가 없는 단일 규칙   | 푸시하지 않는다                            |
| 예시, 템플릿, 출력 양식 | 표의 열 구성                               |
| 가치 판단               | 읽기 쉬움이 성능보다 먼저다                |

분기가 없는 단일 규칙이 수도코드로 바꾼 절차 전체에 걸리면 그 절차 docstring의 `지킬 것`에 넣는다.

## 효과 등급

절차 하나에 든 분기와 반복의 수를 합쳐서 매긴다.

| 등급 | 기준                                                                     |
|------|--------------------------------------------------------------------------|
| 높음 | 분기와 반복이 합쳐서 셋 이상이다                                         |
| 중간 | 분기와 반복이 합쳐서 하나나 둘이다                                       |
| 낮음 | 분기와 반복이 없고 순서만 있다                                           |

- 조건이 어디까지 걸리는지가 여러 뜻으로 읽히는 문장이 있으면 수와 상관없이 높음으로 매긴다.
- 낮음은 수도코드로 바꾸지 않는다.

## 모호한 표현

수도코드로 옮기려면 조건이나 값을 정해야 하는 표현이다. 아래 표는 자주 나오는 예이고, 표에 없어도 이 정의에 맞으면 모호한 표현으로 본다.

| 표현                         | 정해야 하는 것                               |
|------------------------------|----------------------------------------------|
| 필요하면, 필요한 경우        | 필요하다고 보는 조건                         |
| 적절히, 알맞게               | 고르는 기준                                  |
| 가능하면, 되도록             | 못 하는 경우와 그때 할 일                    |
| 충분히, 너무 많으면          | 숫자나 범위                                  |
| 중요한, 큰, 위험한           | 해당하는지 가리는 기준                       |
| 등, 같은 것                  | 나머지 항목                                  |
| 확인한다, 검증한다           | 확인하는 방법, 통과 기준, 통과하지 못했을 때 할 일 |
| A이면 X, B이면 Y             | A와 B가 함께 맞을 때와 둘 다 아닐 때 할 일   |
