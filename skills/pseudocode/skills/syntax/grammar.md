# 수도코드 문법

AI에게 주는 지침 가운데 절차를 수도코드로 쓸 때 따르는 표기와 규칙이다.

## 표기

Python 문법을 빌려 쓴다.

| 표기                         | 뜻                                                      |
|------------------------------|---------------------------------------------------------|
| `def 이름(입력):`            | 절차 하나. 입력은 절차를 시작하기 전에 AI가 구한다      |
| docstring 첫 줄              | 절차의 목적                                             |
| docstring의 `지킬 것:` 목록  | 절차 내내 지켜야 하는 규칙                              |
| 정의가 없는 함수 호출        | AI가 이름의 뜻대로 직접 수행하는 동작                   |
| `if`, `elif`, `else`         | 분기                                                    |
| `for 항목 in 목록:`          | 항목마다 반복                                           |
| `for 시도 in range(횟수):`   | 정한 횟수 안에서 되풀이                                 |
| `return 값`                  | 절차를 끝내고 결과를 넘긴다                             |
| `대문자_이름 = 값`           | 고정된 값                                               |
| `# 주석`                     | 이름만으로 알 수 없는 판단 기준                         |

## 뜻이 정해진 함수

| 함수             | 뜻                                          |
|------------------|---------------------------------------------|
| `ask_user(질문)` | 사용자에게 묻고 답을 받을 때까지 기다린다   |
| `report(내용)`   | 사용자에게 내용을 보여준다                  |
| `stop(이유)`     | 절차를 멈추고 이유를 알린다                 |
| `run(명령)`      | 적힌 명령을 글자 그대로 실행한다            |

## 쓰는 규칙

1. 수도코드는 `python` 코드블록에 쓴다.
2. 이름은 영어 snake_case로 쓴다. 동작 함수는 동사로 시작하고, 조건 함수는 `is_`, `has_`, `can_`, `needs_` 가운데 하나로 시작한다.
3. docstring, 주석, 문자열은 원문 지침의 언어로 쓴다.
4. 줄 하나에는 동작 하나만 쓴다.
   - 한 줄 조건식과 리스트 컴프리헨션은 쓰지 않는다.
   - 함수 호출의 인자 자리에 다른 함수 호출을 쓰지 않는다.
   - 조건 둘을 `and`, `or`로 잇는 것은 된다.
5. 이름만으로 판단 기준을 알 수 없는 조건 함수에는 줄 끝 주석으로 기준을 적는다.
   - 예) `if is_risky(change):  # 되돌리기 어렵거나 다른 사람에게 보이는 변경`
   - 원문 지침에 기준이 없으면 기준을 지어내지 않고 `원문: "표현"` 형식으로 원문 표현을 적는다.
6. 실제 명령, 파일 경로, 숫자, 도구 이름은 바꾸지 않고 그대로 쓴다. 원문에 명령이 적혀 있을 때만 `run`을 쓴다.
   - 예) `run("git status --short")`
7. 되풀이에는 횟수 상한을 둔다. `while`은 쓰지 않는다.
8. 들여쓰기는 세 단계까지 쓴다. 넘으면 안쪽을 함수로 나눈다.
9. 절차가 아닌 내용은 수도코드에 넣지 않고 블록 밖에 자연어로 둔다. 어느 부분을 수도코드로 쓸지는 같은 폴더의 `criteria.md`를 따른다.

## 머리말

수도코드가 든 문서에는 첫 수도코드 블록 맨 위에 아래 머리말을 한 번 넣는다.
이 문법을 읽지 않은 AI도 지침을 같은 뜻으로 읽게 하는 것이다.

```python
# 수도코드 지침: 실행할 코드가 아니라 따라야 할 절차다.
# 정의가 없는 함수는 이름과 주석의 뜻대로 직접 수행한다.
# 순서와 분기를 적힌 대로 지키고, 뜻을 정할 수 없으면 사용자에게 묻는다.
```

## 예시

자연어 지침

> 변경 사항을 목적별로 나눠 커밋한다. 비밀값이 든 파일은 커밋하지 않고 사용자에게 알린다.
> 커밋 메시지는 `~/.claude/commit-message.md`가 있으면 그 규칙을 따르고, 없으면 Conventional Commits 형식으로 쓴다.
> 푸시는 하지 않는다.

수도코드 지침

```python
# 수도코드 지침: 실행할 코드가 아니라 따라야 할 절차다.
# 정의가 없는 함수는 이름과 주석의 뜻대로 직접 수행한다.
# 순서와 분기를 적힌 대로 지키고, 뜻을 정할 수 없으면 사용자에게 묻는다.

def commit_changes(changed_files):
    """변경 사항을 목적별로 나눠 커밋한다.

    지킬 것:
    - 푸시는 하지 않는다.
    """
    if has_file("~/.claude/commit-message.md"):
        message_rule = read("~/.claude/commit-message.md")
    else:
        message_rule = "Conventional Commits"

    files_to_commit = []
    for file in changed_files:
        if has_secret(file):  # API 키, 비밀번호, 토큰
            report(f"비밀값이 들어 있어 커밋하지 않았다: {file}")
        else:
            files_to_commit.append(file)

    groups = group_by_purpose(files_to_commit)
    for group in groups:
        message = write_commit_message(group, message_rule)
        commit(group, message)
```
