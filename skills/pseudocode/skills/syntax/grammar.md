# 수도코드 문법

AI에게 주는 지침 가운데 절차를 수도코드로 쓸 때 따르는 표기와 규칙이다.
읽는 사람이 처음 봐도 소리 내어 읽으면 뜻이 통하게 쓴다. 실행할 코드가 아니므로 문법이 맞는지보다 읽기 쉬운지를 먼저 본다.

## 표기

| 표기                          | 뜻                                                        |
|-------------------------------|-----------------------------------------------------------|
| `def 이름:`                   | 절차 하나. 이름이 곧 절차의 목적이다                      |
| `def 이름(입력):`             | 입력이 있는 절차. 입력은 절차를 시작하기 전에 AI가 구한다 |
| `# 지킬 것: 규칙`             | `def` 바로 아래에 쓰며, 절차 내내 지켜야 하는 규칙         |
| `이름 = 값`                   | 값에 이름을 붙인다                                        |
| 정의가 없는 이름              | AI가 이름의 뜻대로 직접 수행하는 동작이나 구하는 값       |
| `if`, `elif`, `else`          | 분기                                                      |
| `for 항목 in 목록:`           | 항목마다 반복                                             |
| `for 시도 in 최대_3번:`       | 정한 횟수 안에서 되풀이                                   |
| `return 결과`                 | 절차를 끝내고 결과를 넘긴다                               |
| `# 주석`                      | 이름만으로 알 수 없는 판단 기준                           |

## 뜻이 정해진 동작

| 동작                      | 뜻                                          |
|---------------------------|---------------------------------------------|
| `사용자에게_묻기("질문")` | 사용자에게 묻고 답을 받을 때까지 기다린다   |
| `보여주기(내용)`          | 사용자에게 내용을 보여준다                  |
| `멈추기("이유")`          | 절차를 멈추고 이유를 알린다                 |
| `실행("명령")`            | 적힌 명령을 글자 그대로 실행한다            |

## 쓰는 규칙

1. 수도코드는 `python` 코드블록에 쓴다.
2. 이름은 원문 지침의 언어로 쓰고, 낱말 사이는 `_`로 잇는다. 주석과 문자열도 원문 지침의 언어로 쓴다.
   - 예) `한_일_정리`, `어제_직전의_영업일`, `PR_설명`
3. 값은 뜻을 나타내는 이름으로 바로 쓴다. 구하는 방법이 이름으로 드러나면 함수 호출로 쓰지 않는다.
   - 예) `타겟_날짜 = 어제`. `타겟_날짜 = get_yesterday(today)`로 쓰지 않는다.
4. 조건은 읽으면 문장이 되게 쓴다. 값을 견주면 `==`, `>`, `<`를 쓰고, 상태를 따지면 `있음`, `없음`, `필요함`처럼 끝나는 이름을 쓴다.
   - 예) `if 어제 == 휴일:`, `if 바뀐_파일_수 > 최대_파일_수:`, `if 비밀값_있음(파일):`
5. 입력이 없는 절차와 동작은 괄호를 쓰지 않는다. 무엇을 다루는지 밝혀야 뜻이 통할 때만 괄호 안에 쓴다.
6. 줄 하나에는 동작 하나만 쓴다.
   - 한 줄 조건식과 리스트 컴프리헨션은 쓰지 않는다.
   - 괄호 안에 다른 동작을 겹쳐 쓰지 않는다.
   - 조건 둘을 `and`, `or`로 잇는 것은 된다.
7. 이름만으로 판단 기준을 알 수 없는 조건에는 줄 끝 주석으로 기준을 적는다.
   - 예) `if 위험한_변경(변경):  # 되돌리기 어렵거나 다른 사람에게 보이는 변경`
   - 원문 지침에 기준이 없으면 기준을 지어내지 않고 `원문: "표현"` 형식으로 원문 표현을 적는다.
8. 이름만으로 뜻이 통하는 줄에는 주석을 달지 않는다.
9. 실제 명령, 파일 경로, 숫자, 도구 이름은 바꾸지 않고 그대로 쓴다. 원문에 명령이 적혀 있을 때만 `실행`을 쓴다.
   - 예) `실행("git status --short")`
10. 되풀이에는 횟수 상한을 둔다. `while`은 쓰지 않는다.
11. 들여쓰기는 세 단계까지 쓴다. 넘으면 안쪽을 절차로 나눈다.
12. 절차가 아닌 내용은 수도코드에 넣지 않고 블록 밖에 자연어로 둔다. 어느 부분을 수도코드로 쓸지는 같은 폴더의 `criteria.md`를 따른다.

## 머리말

수도코드가 든 지침 문서에는 첫 수도코드 블록 맨 위에 아래 머리말을 한 번 넣는다.
이 문법을 읽지 않은 AI도 지침을 같은 뜻으로 읽게 하는 것이다.

```python
# 수도코드 지침: 이름의 뜻대로 직접 하고, 적힌 순서와 분기를 지킨다. 뜻이 모호하면 사용자에게 묻는다.
```

## 예시

자연어 지침

> 어제 내가 한 일을 정리해. 만약 어제가 휴일이면, 그 직전 영업일의 한 일을 정리해.

수도코드 지침

```python
def 어제_한_일_정리:
    타겟_날짜 = 어제
    if 어제 == 휴일:  # 토요일, 일요일, 한국 공휴일. 내 휴가는 영업일로 본다
        타겟_날짜 = 어제_직전의_영업일  # 휴일 기준은 위와 같다

    한_일_정리(타겟_날짜)
```

자연어 지침

> 변경 사항을 목적별로 나눠 커밋한다. 비밀값이 든 파일은 커밋하지 않고 사용자에게 알린다.
> 커밋 메시지는 `~/.claude/commit-message.md`가 있으면 그 규칙을 따르고, 없으면 Conventional Commits 형식으로 쓴다.
> 푸시는 하지 않는다.

수도코드 지침

```python
def 목적별로_나눠_커밋(바뀐_파일들):
    # 지킬 것: 푸시는 하지 않는다

    if 파일_있음("~/.claude/commit-message.md"):
        메시지_규칙 = "~/.claude/commit-message.md"의_규칙
    else:
        메시지_규칙 = Conventional_Commits

    커밋_대상 = 바뀐_파일들
    for 파일 in 바뀐_파일들:
        if 비밀값_있음(파일):  # API 키, 비밀번호, 토큰
            커밋_대상에서_빼기(파일)
            보여주기("비밀값이 들어 있어 커밋하지 않았다", 파일)

    묶음들 = 목적별로_나누기(커밋_대상)
    for 묶음 in 묶음들:
        커밋(묶음, 메시지_규칙)
```
